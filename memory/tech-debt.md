# Tech Debt

| Item | Area | Impact | Effort | Status |
|------|------|--------|--------|--------|
| `router.push()` fallback to `window.location.href` | Client navigation | Causes redirect failures on Vercel production without the timeout+fallback workaround. Brittle and non-standard. | Medium | **Workaround in place**: 100ms timeout fallback in `site-login/page.tsx`. Root cause unclear — likely Vercel edge/SSR interaction. |
| `router.refresh()` race condition | Site login redirect | Calling `router.replace()` immediately followed by `router.refresh()` causes the redirect to silently fail on Vercel. Removed the `refresh()` call as fix. | Low | **Fixed**: Removed `router.refresh()` from `site-login/page.tsx` |
| `includeFiles` comma syntax gap | Vercel deploy config | `vercel.json` previously used comma-separated patterns for `includeFiles` which Vercel silently ignores. Changed to brace expansion. | Low | **Fixed**: `{dict.marisa,metadata.jsonl}` |
| `resolveStatusAfterPlayerCountChange()` race | Game state transitions | Incorrectly transitions room to "playing" on first player join, causing Start button to not appear. | High | **Fixed**: Logic corrected in `GameState.ts` |
| `joinRoom` missing broadcast after persist | Room join flow | Host never receives updated state after a player joins, so "Start Game" button never appears. | High | **Fixed**: Added broadcast call after `persistRoomState()` in `roomService.ts` |
| Mixed client/server in `site-lock.ts` | Module structure | Original `src/lib/site-lock.ts` contained both shared constants and server-only functions using `crypto.subtle`. | Medium | **Fixed**: Split into `src/lib/site-lock.ts` (server) and `src/shared/site-lock.ts` (shared constants) |
| `envGet` import in test setup | Test infrastructure | `tests/unit/setup.ts` imported `envGet` from `@/app/server/env` which loads `dotenv` at module init time, potentially conflicting with test env setup. | Low | **Mitigated**: Fixed import ordering (imports before env assignments) |
| Timer managed via local refs in `useTimer` | Game timer | Timer was decremented in a local `timeRef` in the hook, not synced to reducer state. Caused timer death lag, desync with UI, and opponent timer not displaying. | High | **Fixed**: Refactored to reducer-based `tickTimer` dispatch. Timer now single source of truth in GameState reducer. |
| Stale `isPaused` closure in `useTimer` | Timer pause | `isPaused` was captured as a value at hook mount time, so state changes (e.g., `isSubmitting`) after mount were invisible to the tick callback. | High | **Fixed**: `isPaused()` is now a function that reads from refs at call time, not a captured boolean. |
| `gameStateRef` pattern ad-hoc across multiple hooks | Hook architecture | `MutableRefObject<GameState>` passed through prop drilling into `useRoomChannel`, `useTypingDraft`, etc. Each hook maintains its own ref sync via `useEffect`. Could be simplified with a shared store. | Medium | **Workaround**: Ref pattern is functional but scattered. Consider Zustand/context for unified state access. |
| `useCountdown` stopwatch missing `pause()` call | Timer countdown | `useEffect` for `isPaused` was only logging — it didn't actually call `sw.pause()` when `isPaused` became true. The stopwatch kept running even when the timer was supposed to be paused. | Low | **Fixed**: Added `sw.pause()` call in the `isPaused` path of the effect. |
| `sw.seconds` dependency in useCountdown | Timer accuracy | `useEffect` was using `sw.seconds` as dependency, but `sw.milliseconds` is what actually changes every frame. This caused the countdown to update only on whole-second boundaries, making the display jittery. | Low | **Fixed**: Changed dependency from `[sw.seconds]` to `[sw.milliseconds]`. |
| Non-auth user stale cookie on "Back to lobby" | Auth flow | When a non-authenticated user presses "Back to lobby", the site-access cookie wasn't being cleared. If the game ended or they navigated back, they'd be treated as still authenticated. | Medium | **Pending verification**: Need to add `deleteCookie` or clear logic on back-to-lobby action for non-auth users. |
| Legacy Socket.IO code still in tree | Code cleanliness | `socketServer.ts.txt` / `socketHandlers.ts.txt` (commented out), active `socketClient.ts` / `socketEvents.ts` may be dead code. `STATE_SYNC_IMPLEMENTATION.md` describes stale Socket.IO flow. | Low | **Not fixed**: Files preserved for reference; `socketClient.ts`/`socketEvents.ts` should be audited to confirm they're unused before removal. |
| `STATE_SYNC_IMPLEMENTATION.md` stale | Documentation | Describes old Socket.IO-based state sync flow that was replaced by Supabase Realtime. Misleads developers. | Low | **Not fixed**: Needs update or archival. |
| Dual logging systems (`LogLayer` vs `createLogger`) | Code consistency | Hooks use `LogLayer` directly; components use `createLogger` wrapper. Two different APIs for the same purpose. | Low | **Not fixed**: Convergence on one pattern would reduce cognitive load. |
| `src/app/foo/` scratch directory | Code cleanliness | Test/scratch area with placeholder files (foo.ts, foo2.ts, bar/ subpage). Should be cleaned up before production. | Low | **Not fixed**: Appears to be a developer playground directory. |
| `src/app/test.ts` root-level test file | Code cleanliness | Loose test file at `src/app/test.ts` outside the test directory. | Low | **Not fixed**: Should be moved to `tests/` or removed. |
| `es6-shim` stubs directory | Code cleanliness | `stubs/es6-shim/` directory with timestamp tracking file. Purpose unclear; may be a build artifact. | Low | **Not fixed**: Investigate necessity. |
| `node-wordnet.d.ts` type declaration | Type safety | Custom type declaration for `node-wordnet` package at `src/types/node-wordnet.d.ts`. Should be in `@types/` or contributed upstream. | Low | **Workaround**: Declaration file kept locally for compatibility. |
