# Decisions

| Date | Decision | Context | Alternatives Considered | Status |
|------|----------|---------|------------------------|--------|
| 2026-06 | Split `site-lock.ts` into server + shared modules | Client components (`AppShell.tsx`) only needed `SITE_LOGIN_PATH` constant; importing the full module pulled in server-side deps (`crypto.subtle`, `envGet`). Risk of leaking server code into client bundles. | Keep single file with conditional exports; use `"use server"` directives | **Done**: `src/lib/site-lock.ts` (server functions) + `src/shared/site-lock.ts` (shared constants: `SITE_ACCESS_COOKIE`, `SITE_LOGIN_PATH`) |
| 2026-06 | Extend site password lock to API routes | Room info/join API endpoints were not gated by site lock; anyone with a room URL could bypass the password gate and join games. | Per-route middleware; global middleware | **Done**: Added `checkSiteAccess()` to `site-lock.ts`, integrated into join API, room GET API, and proxy. Room invite paths bypass the lock for playing rooms. |
| 2026-06 | Replace Next.js middleware with `proxy.ts` route handler | Needed finer control over auth decisions per request; Next.js middleware had limitations around cookie access, request inspection, and conditional pass-through for invite paths. | NextAuth middleware; custom edge middleware | **Done**: `src/proxy.ts` handles all auth gating including site lock, invite bypass, and auth path allowlisting |
| 2026-06 | Dictionary Python service on Vercel serverless | Korean end-to-end word game requires efficient dictionary lookup. JavaScript trie libraries were too slow or incompatible with serverless runtime. | Node.js trie (trie-search, etc.); external dictionary API | **Done**: FastAPI + marisa-trie on Vercel Python runtime at `api/index.py` |
| 2026-06 | Supabase Realtime over Socket.IO for game state broadcast | Socket.IO required persistent connections and a separate server; Supabase Realtime channels integrate natively with existing Supabase setup. | Socket.IO with dedicated server; WebRTC; polling | **Done**: One Supabase real-time channel per room, broadcast via `broadcastRoomGameState()` |
| 2026-06 | `killPlayerAndNextTurn` as atomic operation in GameState | Race condition between player kill and turn advancement could leave stale state between dispatches. Merged kill + nextTurn into single reducer action. | Two separate dispatches with locking; state snapshotting | **Done**: Single reducer action `killPlayerAndNextTurn` in `GameState.ts` |
| 2026-06 | Timer bar uses CSS `@keyframes shrink-width` animation | CSS `transition` on `width` caused drift between JS tick intervals and animation frames. `@keyframes` with duration set to `remainingSeconds` stays in sync with the countdown value. Animation pauses via `animationPlayState: paused`. | CSS `transition` on width; canvas-based timer; requestAnimationFrame polling | **Done**: `TimerBar.tsx` uses `@keyframes shrink-width` |
| 2026-06 | Move dictionary runtime files to `dictionary/data/`, source files to `dictionary/data/_src/` | Source XML files (17MB+) were being included in Vercel deployments unnecessarily. Runtime only needs `dict.marisa` (~2MB) and `metadata.jsonl`. | Vercel `includeFiles` filtering; separate data repo | **Done**: `_src/` excluded via `.vercelignore` |
| 2026-06 | Refactor timer from local refs to reducer-based `tickTimer` | Timer was managed via local `timeRef` in `useTimer` hook, causing stale state issues and desync with reducer state. Moved to reducer dispatch for single source of truth. | Keep local refs with sync-back to reducer; use separate timer store | **Done**: `useTimer` dispatches `tickTimer` to `gameStateReducer`; reducer handles decrement, expire detection, and auto-kill |
| 2026-06 | Opponent timer display in PlayerCard | Players couldn't see other opponents' remaining time during their turn. Added `timeRemaining` prop to PlayerCard with compact timer bar matching TimerBar style. | Separate opponent timer panel; tooltips | **Done**: PlayerCard compact mode renders a mini TimerBar using the same CSS transition |
| 2026-06 | `router.push()` fallback to `window.location.href` with 100ms timeout | `router.push()` was silently failing on Vercel production deployments. Added timeout check: if browser URL doesn't match target after 100ms, fall back to hard navigation. | Full `window.location` replacement; SSR redirects; `router.replace` | **Done**: 100ms timeout + `window.location.href` fallback in `site-login/page.tsx` |
| 2026-06 | Host auto-removes disconnected players via presence tracking | Players who disconnect (close tab/browser) could remain in game state indefinitely. Host's `useRoomChannel` now detects presence-leave events, checks if player is still in game state, and dispatches removal + broadcast. | Server-side cleanup only; manual host kick button | **Done**: Host presence-leave handler in `useRoomChannel.ts` reads `gameStateRef` to verify player still exists before removing |
| 2026-06 | `NEXT_PUBLIC_MOCK_SUPABASE` env flag for client-side mock detection | Server-only `MOCK_SUPABASE` flag wasn't accessible from client code. Added `NEXT_PUBLIC_` prefix variant so client components can also detect mock mode. Site lock automatically disabled in mock mode. | Client-side Supabase mock client; separate mock env config | **Done**: `isMockSupabase()` checks both flags; `isSiteLockEnabled()` returns false when mock is active |
| 2026-06 | Ref pattern (`gameStateRef` as MutableRefObject) for stale closure prevention in hooks | Callbacks passed to hooks like `useRoomChannel` and `useTimer` captured stale state from React renders. Passing `MutableRefObject` refs ensures callbacks always read latest state at call time. | `useCallback` with full dependency lists; Redux/Zustand for cross-component state | **Done**: `gameStateRef` pattern used in `useRoomChannel`, `useTimer`; `isPaused()` is a function that reads from ref, not a boolean stored at mount time |
| 2026-06 | Extract join/leave logic from GameContainer into dedicated hooks | GameContainer.tsx had 274 lines of mixed effects, state, and API calls. Extracted `useJoinRoom` (connection state, join flow, start game) and `useLeaveRoom` (tab close, unmount cleanup, Strict Mode debounce) into separate hooks. | Keep monolithic GameContainer; use custom class/controller | **Done**: `useJoinRoom.ts` (138 lines) + `useLeaveRoom.ts` (41 lines); GameContainer reduced to thin orchestrator |
| 2026-06 | Click-to-copy invite link in GameOverlay waiting popup | Hosts had no easy way to share game URL with invitees. Added `roomId` prop to GameOverlay, `inviteUrl` computed from `window.location.origin/room/:id`, copy-to-clipboard via `navigator.clipboard.writeText()`. | Share button via Web Share API; QR code; manual URL copy | **Done**: Invite link field with click-to-copy in GameOverlay, wired through GameV2 and SpectatorView |
| 2026-06 | Structured client logging via `@/lib/client/logging` | `console.log` with bracket prefixes was inconsistent and couldn't be filtered/disabled centrally. Created `logger` module with `debug/info/error` methods, level filtering, and structured data support. | winston/pino on client; keep raw console.log | **Done**: `logger` imported across client components (GameContainer, GameV2, InputSection, SpectatorView, TimerBar, etc.) |
| 2026-06 | Theme toggle moved from `layout.tsx` fixed position to AppNav/AppShell | ThemeToggle was always rendered in root layout at `fixed top-4 right-4`. This was redundant when AppNav was already visible. Moved into AppNav (in nav bar) and AppShell (fixed position fallback on standalone screens like `/site-login`). | Keep in layout.tsx; use portal to body | **Done**: ThemeToggle removed from layout.tsx, added inside AppNav nav bar and as standalone in AppShell when nav hidden |
| 2026-06 | `cleanup_stale_rooms()` SQL function for auto-deleting old rooms | Stale rooms accumulated in Supabase with no automatic cleanup. Created PostgreSQL function: delete rooms where `updated_at < now() - interval '30 minutes'` OR `playercount = 0`. | Cron job via pg_cron; client-side cleanup on lobby load | **Done**: Migration `20260616230001_cleanup_stale_rooms.sql`; fix applied: changed `playercount is 0` → `playercount = 0` |
| 2026-06 | Word submission sends current countdown timer in POST body | Server had no visibility into client-side timer state during word submission. Now client sends countdown value in POST body; server updates `timeRemaining` for that player before broadcast. | Separate timer sync endpoint; WebSocket timer channel | **Done**: `submitWordApi` POST includes countdown; server calls `setTimerForPlayer()` before broadcast |
| 2026-06 | TimerBar `@keyframes` animation driven by `remainingSeconds`, not `duration` | CSS animation duration was set to `timer.duration` (full round time), so the bar never reached 0% — it was animating at the wrong rate. Changed to `timer.remainingSeconds` so animation matches actual remaining time. | Use CSS transition instead of animation; JS-driven bar without CSS animation | **Done**: `shrink-width ${timer.remainingSeconds}s linear forwards` |
| 2026-06 | `useCountdown` via `react-timer-hook` `useStopwatch` | Needed a reliable, pausable countdown timer for per-player submission tracking. `react-timer-hook`'s `useStopwatch` provides `start`, `pause`, `reset`, and reactive `seconds`/`milliseconds` values. Replaced custom timer implementation. | Custom `setInterval` hook; `useTimer` refactor to serve dual purpose | **Done**: `useCountdown.ts` wraps `useStopwatch`; starts on `gameStatus === "playing"`, pauses on `isPaused` |
| 2026-06 | Player list display in waiting overlay with consistent modal dimensions | Host couldn't see who was in the waiting room. Added filtered player list (excluding nulls) in `waitingJsx()` of GameOverlay. All overlay modals (waiting, finished, dissolved) now share `min-w-[22rem] max-w-md` for visual consistency. | Separate waiting room page; sidebar panel | **Done**: Player names listed below spinner in waiting overlay with consistent min/max width |
| 2026-06 | `createLogger(name)` factory pattern for client logging | Original `import { logger } from "@/lib/client/logging"` required passing module name as first arg on every call. Refactored to `createLogger(name)` which bakes the prefix into the logger at creation time, reducing boilerplate and preventing inconsistent prefixes. | Keep global logger with arg; use winston child loggers | **Done**: `createLogger` used across components; hooks use `LogLayer` directly |
| 2026-06 | Room API client uses `LogLayer` for structured logging | API client benefits from structured metadata (request params, response data). Added `LogLayer` + `ConsoleTransport` from `loglayer` npm package for `withMetadata({...}).info()` calls with JSON serialization. | Keep `createLogger` pattern; write custom serialization | **Done**: `RoomAPI` logger uses LogLayer |
| 2026-06 | Block non-auth users from `/lobby` | Users without site password authentication could access the lobby page directly. Proxy now redirects unauthenticated users away from `/lobby` via site lock. Spectator cookie cleanup also fixed to prevent stale room access tokens. | Allow lobby access with degraded features; server-side lobby gating | **Done**: Proxy enforces site lock on `/lobby`; non-auth users blocked |
| 2026-06 | Timer pauses on invalid word submissions | Previously the timer continued running even when a player submitted an invalid word (already used, too short). Now timer pauses during submission and resumes only on valid submission or error. Prevents timer drain from failed attempts. | Hard timeout on submission; ignore invalid submissions silently | **Done**: `isSubmitting` state gates timer pause; invalid words trigger error without advancing turn |
| 2026-06 | Room action path validation via `extractRoomIdForAction()` | Room action endpoints (submit, leave, timer-expiry, spectate, dissolve) needed per-room cookie validation to ensure only room members could take actions. Proxy uses regex to extract roomId from action paths and validates the room access cookie. | Per-route middleware; validate inside each API route | **Done**: `extractRoomIdForAction()` in proxy.ts matches `/api/rooms/{roomId}/{action}`; validates `roomAccessCookie` |
